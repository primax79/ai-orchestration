Observed with the real CLIs through the run engine (`ai-orch run start --continue`), in a scratch git repo under the 07.5 worktree's `.tmp/`. Versions: claude 2.1.296 (model haiku), kilo 7.8.8 (model `google/gemini-3.8-flash`), codex-cli 0.147.0 (model `gpt-5.6-luna`, ChatGPT login). Each resume is a new OS process, so every row is also a "resume from a fresh process". Raw streams: `scripts/fixtures/runs/` (scrubbed).

"Memory check" means the resumed turn was asked, without tools, what happened earlier in the session, and answered correctly.

## Normalized usage (spec §0c E8)

Implemented in `usage_from_objects` (`scripts/orchestration_runs.py`), stored per run as `run.json` `usage`:

| Field | Kilo (`step_finish.part`) | Claude (`result`) | Codex (`turn.completed`) |
| --- | --- | --- | --- |
| `input_tokens` (uncached) | Σ `tokens.input` | `usage.input_tokens` | Δ(`input_tokens` − `cached_input_tokens`) |
| `cache_read` | Σ `tokens.cache.read` | `usage.cache_read_input_tokens` | Δ `cached_input_tokens` |
| `cache_write` | Σ `tokens.cache.write` | `usage.cache_creation_input_tokens` | Δ `cache_write_input_tokens` (0 so far) |
| `output_tokens` | Σ (`tokens.output` + `tokens.reasoning`) | `usage.output_tokens` | Δ `output_tokens` |
| `estimated_context_tokens` | last step's `tokens.total` | last of `usage.iterations` (input + cache read + cache write + output) | rollout `token_count.info.last_token_usage` (best effort; None if not found) |
| `cost_usd` | Σ `part.cost` | `total_cost_usd` | not reported (None) |

**Codex usage is cumulative over the thread, not per turn** (a one-line resumed turn reported 120,663 input tokens after a first turn of 104,655; the rollout's `total_token_usage` matches the stream). Δ is the difference from the nearest earlier run of the continuation chain that recorded `usage.session_totals`. Rotation (E8) must use `estimated_context_tokens`, never these sums.

Observed sizes: a trivial Kilo execute turn ended at ~38k context tokens, a Claude haiku one at ~65k (Claude Code's own system prompt and tools), a Codex one at ~16k.

## Engine fixes made in 07.5 (local to the parsers and continue checks)

- `session-busy`: `run start --continue` refuses while another active run of the same tool holds the same `session_id` (spec §0 "never two resumptions of the same session at the same time").
- Session mismatch: when a continuation's stream reports another session id, the run is `failed` with `session_mismatch: true`, `observed_session_id` and an `invariant_error` (catches the Codex name fallback; Claude's non-UUID case already exits 1).
- `agent_error` recorded on failed runs (stream error event, else the last stderr line), so 12.5 can classify "session not found" without reading logs.
- Kilo resume argv: `--` before the message (it failed with `File not found: Continue.`).

## Engine follow-ups not done here (not local to the parsers)

1. **Cancel leaves Kilo tool processes running.** Process-group kill misses children Kilo starts in their own group (`sleep 45` survived `run cancel`, reparented to pid 1). Kill the agent's descendant tree (walk by ppid before signalling) or run the agent under a dedicated session and kill by session id.
2. **Continuing a verify run, or any run whose worktree was removed, runs in an empty directory.** The supervisor `mkdir`s a missing `cwd`; for a verify run the throwaway worktree is gone after completion. Refuse the continuation (or recreate the worktree at `target_commit`) instead.
3. **A verify run removes `worktree_path` at completion even when that path is another run's execute worktree** (seen with a hand-forged verify record that inherited an execute run's worktree): guard the removal to worktrees the verify run created.
4. **The task file transition makes the target repo dirty.** When `tasks/` lives in the target repo, the `in progress` transition the supervisor writes leaves the repo dirty, so a second `execute` in the same repo is refused (`dirty-repo`) until someone commits the task file. Ignore `tasks/` in the cleanliness check or commit the transition.
5. **A failed `execute` leaves the task `in progress`** with no way back to `open` (`in progress -> open` is illegal); a retry needs a new task or a manual edit.
6. **Kilo resume needs the original project.** Resuming in another repository fails with an opaque server error; the orchestrator role (12.5) must keep its turns in one project directory and treat this error as "session not found".
7. **Profile defaults reach expensive models silently.** A `verify` without `--profile` resolves to `deep-reasoning`, and when the configured file lacks that profile the built-in defaults (`opus`/`high`, `google/gemini-4-argon`/`high`) apply. Worth a preview warning when the model comes from built-in defaults.
