- **Nothing is pushed and main is never touched.** The hub cannot push to GitHub over ssh (`github.com` is not in its `known_hosts`); it pulls over https.

## Per-task state on the hub

`.tmp/executors/<slug>.chain` holds one of:

- `running`
- `checking`
- `merged`
- `no-commit`
- `dirty-worktree`
- `tests-red (...)`
- `merge-conflict`
- `post-merge-red-undone (...)`
- `no-brief`
- `worktree-failed`

Each task also has these files: `<slug>.log` (Kilo output), `<slug>.status` (exit), `<slug>.tests.log`, and the Final Report inside the branch (`tasks/.../notes/<id>-final-report.md`).

## Resuming (any session)

1. `ssh alf_ubuntu 'cat ~/works/ai-coding-tools/ai-orchestration/.tmp/executors/chain.log'`
2. Fetch the branches from the hub: `git fetch alf_ubuntu:works/ai-coding-tools/ai-orchestration 'refs/heads/kilo/*:refs/remotes/hub/kilo/*' integration/19:refs/remotes/hub/integration-19`.
3. Independent verification of each `merged` task against its Verification section. The chain only checked that the tests are green; nobody has reviewed the code yet. Then transition the tasks: `in progress → delivered → verified`.
4. Bring `integration/19` onto main (`merge --ff-only` if possible), push, and close the tasks in the registry.
5. Handle the failure states: a resume prompt to the same Kilo session (`kilo run -s <session> ...`) or a corrected re-dispatch.

## Known caveats

- Registry states in git: 19.1, 19.4, T087, T088 are `in progress`. The tasks the chain launches are still `open` in git. Update them when resuming.
- Baseline 2026-10-29: 4 tests red on main (T088 is fixing them): `test_orchestration_env.py` x2 (duplicate skills not fixable), `test_orchestration_invoke.py::test_get_process_descendants_and_kill` (Linux only), `test_orchestration_orchestrator.py::test_bounds_kill_runaway_stub` (timing). The chain treats a suite as green when every failure is already in `.tmp/baseline-tests.log` on the hub, and logs it as "only baseline failures". So "merged" does not mean "suite fully green" until T088 is in.
- The chain is a one-off script in `.tmp/` (not versioned), a stopgap until 19.6/19.10-19.12 exist. Stop it with `screen -S orch-ai-orchestration-chain -X quit`; the per-task states persist and a restart resumes from them.
