#### Proposed Task 1 — `kilo-mcp` (covers Asks A.1, B.2, and `executor-housekeeping-and-completion.md` §4)
- **Title (IT):** `kilo-mcp: stato del worktree (commits_ahead, dirty_files, stato del task sul branch e failed_with_uncommitted_work) in kilo_task_status, kilo_task_wait e kilo_task_progress`
- **Short:** `Stato worktree nei tool task`
- **Target repo / registry:** `kilo-mcp` (workspace registry `../tasks/tooling/`)
- **Priority:** **P1**
- **Priority reason:** When a background Kilo run dies mid-work on a network/TLS error or when `kilo.db` has no matched session row, the orchestrator still has no visibility into uncommitted files, commits ahead of base, last error line, or on-branch task state without running manual git commands in every worktree.
- **One-line goal:** Enrich `kilo_task_status`, `kilo_task_wait`, `kilo_task_result`, and `kilo_task_progress` (fallback when session is missing) with worktree git state (`commits_ahead`, `dirty_files`, `last_commit_age`), the task file's `state:` on the branch, the last error line from the log, and the `failed_with_uncommitted_work` status distinction.

#### Proposed Task 2 — `kilo-mcp` (covers Asks A.2 and E.2)
- **Title (IT):** `kilo-mcp: ripresa di run interrotte nello stesso worktree (resume_task_id) e risoluzione assistita dei conflitti con refresh_base`
- **Short:** `Ripresa worktree e sync branch`
- **Target repo / registry:** `kilo-mcp` (workspace registry `../tasks/tooling/`)
- **Priority:** **P2**
- **Priority reason:** Resuming a failed run that left uncommitted work or resolving base-branch merge conflicts still requires the Architect to hand-craft boilerplate prompts and look up worktree paths manually.
- **One-line goal:** Add `resume_task_id` (or `continue_in_worktree`) to `kilo_implement`—which reuses the prior task's worktree, reloads its `brief_file`/spec, and prepends the uncommitted-work recovery preamble—and add a conflict-resolution mode to `refresh_base` that delegates conflict resolution of listed files to the resumed executor session.

#### Proposed Task 3 — `kilo-mcp` (covers Asks I.2 and I.4)
- **Title (IT):** `kilo-mcp: registrare duration_s per i task in background in metrics.jsonl e assegnare un titolo leggibile alle sessioni Kilo`
- **Short:** `Durata metriche e titolo sessioni`
- **Target repo / registry:** `kilo-mcp` (workspace registry `../tasks/tooling/`)
- **Priority:** **P3**
- **Priority reason:** `kilo_metrics` reports `avg duration: 0s` because background runs omit `duration_s`, and isolated worktree runs leave dozens of untitled `New session - <timestamp>` rows in `kilo.db`.
- **One-line goal:** Compute and write `duration_s` in `_reconcile_task_if_orphaned` when logging background runs to `metrics.jsonl`, and set/update the Kilo session title from the task ID / branch / brief name (`<task_ref> (<run_id>)`).
